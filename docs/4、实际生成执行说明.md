# 本轮实际生成执行说明

本轮用户已授权实际生成全部 500 题的数据，并要求多个 subagent 分担，每个 subagent 负责两个领域，达到并发上限后等待已有任务完成再开启下一批。

这项授权替代生成计划中“当前仅准备资料”和“做完一组等待用户再开启”的旧执行范围。其余数据规范保持有效，不启动正式模型训练。

## 分工和交付

- 共 25 个双领域批次，每批 20 题、200 条请求、240 个问题。
- 同时最多运行 3 个 subagent，主 agent 负责派发、汇总、跨批检查及语义抽查。一个 subagent 只负责分配的两个领域，不再派生其他 subagent。
- 分工表：`reports/generation/dispatch.json`。仅改分配给自己的草稿、分片和独立创作脚本、审阅报告，避免并发改同一文件。
- 完成后应有 500 个正式分片，按固化划分准备 4,000 / 500 / 500 条请求，以及 4,800 / 600 / 600 个训练问题。

## 必须执行的质量约束

先阅读 `docs/1、决策训练数据生成计划.md`、负责的 `data/topics.jsonl` 条目、`openjev/data.py` 和 `scripts/finalize_shard.py`。每题十条必须在事实、措辞、任务边界和干扰因素上有实质变化。程序可以辅助序列化、计算派生响应和验证，不能以改标题、换人名或拼无关背景代替创作。

遵守固定槽位：01—04 Choice，05—07 Score 低/中/高，08 Noul 明确肯定，09 Noul 明确否定，10 同一状态下三个独立题型各一问。槽位03真正缺信息；槽位09必须有直接反证；每五题至少一条槽位10 Noul 判断尚未知的事实，以覆盖各组证据不足场景。所有正式标签标记 `agent_synthetic`，不输出 `confidence`。

**证据充分性与事实真伪不可混淆。** “现有记录是否足以确认仍在保修期？”若缺日期，是明确不足，应给低 Noul 值。“目前是否仍在保修期？”若缺日期，则事实未知，可以约 0.5。若 Choice 中已有“信息不足”类别，能够确定缺信息时可以高概率选择它，无须把概率机械均分到实体类别。

同理，明确说“不作商品评价”时，“是否表达对商品满意”应否定；“本人对商品是否满意”才可能未知。Score 的“没有形成执行请求”与“有倾向但尚未要求执行”有重叠，应把最低级限定为没有具体处理方向，按互斥边界编写等级。最高完整度标签要求该等级列举的每项信息均在状态中出现，不能在 review 中补出 state 没有的事实。

情感题应明确说话者、对象、时间，区分中性、混合和不足；意图题区分咨询、计划、执行、否定、取消和改口。Score 只能衡量一个有序维度，不能将无序类别编号作为分值。题目编号不得写入 state。

Choice 若存在层级包含关系，须明确排除条件或判断优先级。例如“已改期”可能也满足“预约成功”，“地址待补”可能也属于“待确认”，不能直接并列而不说明边界。提供的规则应使当前场景有可解释的唯一类别，或明确使用信息不足类别。

完整度评分若分为零项、一项、全部，低档应明确“两项均未提供或均不充分”，避免“未提供A或B”与中档仅有一项重叠。“及时”“合规”“齐全”必须在该请求内给出具体时限、阈值或必填清单，不能依赖同一命题其他样本中的规则。

每题至少一条结构化 state；每个双领域批次至少五条数组 state、五条结构化 instructions、五个结构化候选描述。概率向量应与具体证据强弱一致，避免全部固定向量或 Choice 一律首项获胜。

## 长度覆盖

完整候选编码输入不得超过 8,192 token。推荐每题 7 短、2 中、1 长；这是覆盖建议，不允许为凑比例重复结论或拼无关文字。

本轮每个领域至少包含一条自然中等输入（1,025—4,096 token）和一条自然长输入（4,097—8,192 token），其他题尽量满足推荐覆盖。以本地 tokenizer 实测为准，最终报告真实分布及与推荐的差距。长样本可以使用有信息变化的多轮对话、详细规则与多条关联记录，但不靠频繁重复正确答案延长文本。

## 验证和审阅

使用项目 `.venv\Scripts\python.exe`。先发布到各题对应分片，调用 `validate_shards` 检查所负责的20题，用 `encode_candidates` 逐候选检查长度。不要用按25题划分的组校验来代替20题任务校验。

每个 subagent 至少语义复核4个完整命题，并检查其余每题至少一个边界样本；报告被审阅ID和发现/修复的问题。主 agent 独立抽查并执行全量查重、覆盖与长度检查。发现已发布数据错误，先保存可追溯备份，再同步修复草稿和分片，重新校验；禁止覆盖其他agent负责的数据。

全局审计工具 `scripts/audit_generation.py` 由主 agent 运行。其告警仅是复核线索，自动通过不代表所有语义正确。完成后保留合成标签性质说明和实际审阅范围，不宣称真实业务准确率或已校准概率。
