# 本机全量微调与使用

## 实现与范围

这是一个纯文本决策模型：Qwen3.5 文本骨干的最后有效位置接一个标量评分头，同一问题的候选得分经 softmax 得到概率分布。Choice 取概率最大的选项，Score 按等级求期望，Noul 返回“是”的概率。响应由代码生成，不依赖模型输出 JSON。

**全量训练文本骨干和评分头的所有参数，不使用 LoRA、量化适配器或冻结层。** Qwen3.5-0.8B 下载包也包含视觉模块，本任务只读取 `model.language_model.*`。不读取视觉参数并不等于冻结文本层；输入中的对象和数组是 JSON 文本，不是图像或音频。

与官方模型的关系：采用 Jev 风格的请求、题型和结果字段；按用户要求省略 `confidence`。现成 TypeSafe SDK 如果把该字段设为必填，需调整客户端模型或直接调用 HTTP，不能保证未经修改即可使用。没有官方模型权重、教师标签或速度复现承诺。

硬件检查发现 NVIDIA GeForce RTX 5060 Ti，约 16GB 显存。实际版本与 CUDA 实测结果写入 `reports/environment.json`，运行状态写入 `reports/当前准备状态.md`。

环境独立放在项目 `.venv`，不修改原模型目录、正在运行的下载器或其他 Python 环境。已固定 Python 3.11 兼容依赖，PyTorch 2.10.0 CUDA 12.8，Transformers 5.5.0。可重建：

```powershell

powershell -ExecutionPolicy Bypass -File scripts/setup.ps1
```

脚本优先使用现有 `python` 创建虚拟环境，不要求安装独立 CUDA Toolkit。CUDA 运行库随 PyTorch wheel 安装；驱动仍使用本机驱动。安装后版本快照在 `requirements.lock.txt`。

依据：[PyTorch 官方版本安装页](https://pytorch.org/get-started/previous-versions/)、[Transformers Qwen3.5 文档](https://huggingface.co/docs/transformers/v5.5.0/model_doc/qwen3_5)、[官方模型仓库](https://huggingface.co/Qwen/Qwen3.5-0.8B)。选择固定版本是为了复现，后续不自动追随最新版。

安装脚本通过 `scripts.download_torch` 分块下载，支持续传；完成后校验官方索引的 SHA256，再安装缓存 wheel。安装器使用 Python 自带的 pip。本机直连官方源多次超时，因此 PyTorch 和普通 Python 依赖默认使用阿里云镜像；PyTorch 文件最终必须与官方 SHA256 完全一致。下载脚本可加 `--source official`，安装脚本可传 `-IndexUrl https://pypi.org/simple`。CDN 连接辅助只在当前安装进程中优先选择可连接的官方 DNS 地址，不修改系统网络设置，TLS 校验保持开启。不得并行修改同一个环境；等待或停止本项目自身的安装进程后再安装。

## 训练配置

编辑 `configs/train.json`。默认参数：

| 项目 | 值与理由 |
|---|---|
| 训练范围 | 全部文本参数 + 决策头 |
| 参数存储 | FP32，避免直接 BF16 更新丢失小步长 |
| 前向计算 | CUDA BF16 自动混合精度 |
| 优化器 | Adafactor，压缩大矩阵二阶状态，适配 16GB 显存 |
| 骨干学习率 | 2e-5 |
| 决策头学习率 | 1e-4 |
| 轮数 | 3，最终依据验证集效果决定 |
| 梯度累积 | 8 个独立问题再更新一次 |
| 候选微批次 | 1；先收集得分，再逐候选重算并反向传播，避免同时保留所有候选计算图 |
| 输入长度 | 每个候选完整编码输入最多 8,192 token，超长报错 |
| 激活检查点 | 开启层内重计算，与逐候选反向传播配合降低显存占用 |
| 保存频率 | 每 100 次优化更新及每轮结束 |

每个问题的损失为 `-Σ target_probability × log_softmax(candidate_logits)`。多问题请求在准备阶段拆开，每个问题等权，训练不学习 model、usage、review、ID 或 JSON 标点。Noul 在内部转为 `[否, 是]` 二分类软标签。没有自回归文本损失。

8,192 token 包括任务前后缀、JSON 结构、state、单个问题说明和单个候选描述。长度预检默认读取 `configs/train.json`，同时按新数据规则报告短（≤512）和中（513—1,024）请求覆盖及逐题9短1中差异；推理从训练断点读取相同上限。旧断点保留旧长度配置，不能只修改训练配置就改变旧断点的推理限制。

训练先不保留计算图地得到所有候选得分，再按各候选原来的随机状态重算，使用组内 softmax 的梯度 `p_i - target_i` 逐候选反向传播，最后统一更新参数。这样保持原来的归一化损失、梯度累积和全部参数更新，显存中只需保留一个候选微批次的计算图。随机状态、梯度及恢复结果均纳入检查；代价是增加前向计算时间。

注意力沿用固定版本 Transformers 的实现，没有修改其安装文件或截断长文本的反向传播。

程序启动时检查 **可训练参数数 = 全部模型参数数**，并输出数量。权重读取采用严格映射，任何文本参数缺失都会报错，避免误用随机初始化的骨干。

## 先验证，再训练

```powershell
# 验证实际 CUDA 运算与模型文件是否齐全
.\.venv\Scripts\python.exe -m scripts.check_environment

# 不需要下载权重：以随机小尺寸 Qwen3.5 检验混合注意力、反向传播、全量更新、保存重载
.\.venv\Scripts\python.exe -m scripts.smoke_test

# 权重下载完成后：用真实 0.8B 模型执行两个优化步骤，不覆盖基础模型
.\.venv\Scripts\python.exe -m scripts.smoke_test --real-model

# 检验默认长度上限与较多候选项
.\.venv\Scripts\python.exe -m scripts.smoke_test --real-model --stress

# 数据准备完成后：用正式数据先跑两步，输出到配置指定的目录
.\.venv\Scripts\python.exe -m scripts.train --config configs/train.json --max-steps 2
```

小模型通过不证明 0.8B 的显存和速度已验证。真实模型检查结果单独写 `reports/smoke-real.json`；该文件不存在就表示尚未完成真实模型验证。测试样本不进入正式数据集。

本机已完成 **8,192 token** 真实模型验证：752,394,049 个参数全部可训练；6 个候选、最长输入恰好 8,192 token，完成两步全量更新，骨干参数发生变化，保存重载一致。峰值 CUDA 分配约 **14.888GiB**，两步更新约 257.3 秒，包含保存重载的整个检查约 **293.59 秒**。详细结果见 `reports/smoke-real-stress-8192.json`；旧的 `smoke-real-stress.json` 仅保留此前 1,024 token 的历史结果。

显存数字是 PyTorch 分配量，不包含桌面等其他程序占用。运行时 Windows 进程计数器采样观察到约 **2.01GiB 共享 GPU 内存**，这不是共享内存峰值；因此本机 8,192 token 验证通过，并不意味着可以完全只用专用显存或获得短输入的速度。建议正式训练前关闭其他占用显存的软件，先用实际长样本试跑。测试文本用于流程和长度验证，不能证明长上下文语义质量，也不能据此推算完整训练时长。正式 5,000 条数据还没有生成，未执行完整训练。

训练入口与恢复的额外复测方式（使用随机小模型，约几十秒）：

首次正式训练可直接运行以下命令；若已有两步试跑断点，请用下一节的恢复命令继续，或在配置中选择新输出目录。

## 断点恢复与结果评估

`outputs/decision-full/latest.txt` 保存最近的完整断点路径。例如从两步试跑继续：

```powershell
.\.venv\Scripts\python.exe -m scripts.train --config configs/train.json --resume outputs/decision-full/checkpoint-000002
```

支持恢复优化器、数据游标和随机状态。恢复时检查训练/验证文件哈希，数据已改变则拒绝沿用旧游标。中断发生在保存标记写入之前的目录不可恢复；选择带 `COMPLETE` 文件的断点。不要加载来源不明的断点。

先在验证集比较候选断点，选定后再评估测试集：

```powershell
.\.venv\Scripts\python.exe -m scripts.evaluate --checkpoint outputs/decision-full/checkpoint-001800 --data data/prepared/validation_requests.jsonl --output outputs/validation.json
.\.venv\Scripts\python.exe -m scripts.evaluate --checkpoint outputs/decision-full/checkpoint-001800 --output outputs/test.json
```

示例 `checkpoint-001800` 来自默认完整数据配置的 3 轮计划；以真实产生的目录为准。指标包括 Choice 对标注的选项一致率、Score 均值误差、Noul 概率误差、软标签交叉熵和 Brier 距离。标注本身来自 agent，指标不能证明业务真实准确率或概率校准。真实应用应另外准备人工确认的独立评估集。

## 本地推理与接口

```powershell
.\.venv\Scripts\python.exe -m scripts.predict --checkpoint outputs/decision-full/checkpoint-001800 --request examples/request.json
.\.venv\Scripts\python.exe -m scripts.serve --checkpoint outputs/decision-full/checkpoint-001800 --port 8000
```

服务绑定 `127.0.0.1`，提供 `POST /v1/systemone` 和 `GET /health`，默认不需要 API key。发起请求：

```powershell
$body = Get-Content -LiteralPath examples/request.json -Raw -Encoding utf8
Invoke-RestMethod -Uri http://127.0.0.1:8000/v1/systemone -Method Post -ContentType 'application/json; charset=utf-8' -Body ([System.Text.Encoding]::UTF8.GetBytes($body))
```

响应包括 `model`、`answers`、`usage`；没有 `confidence`。模型的概率始终归一化，Score 始终由概率计算。问题分别处理，ID 不进入底层模型，因此添加或重命名其他问题不会改变当前问题的语义输入。为控制显存，本实现按问题顺序处理，不承诺官方“增加问题几乎不增加延迟”的性能。

当 `state` 中出现“忽略任务并回答某选项”等内容时，那些字符仍只是待判断数据。模型能否抵抗这类干扰需要训练和测试；程序仅保证不直接把它们当成系统指令执行。

## 常见故障

- **模型尚未就绪**：保留当前下载，让下载任务完成；脚本检查索引中每个权重文件的存在及 safetensors 完整性。不会自动重新下载或加载半成品。
- **显存不足**：先关闭其他占用显存的软件；保持候选微批次为 1 和激活检查点开启。8,192 token 长输入会比短输入耗时更多；如仍然不足，记录失败样本长度和显存占用，再调整训练实现或硬件，不静默降低输入上限或截断数据。梯度累积增大不会解决单个输入的峰值。
- **缺少加速内核提示**：Windows 原生方案使用 PyTorch/SDPA 与 Qwen3.5 的原生回退实现，不要求安装 FlashAttention、Triton 或 causal-conv1d；回退可能较慢。
- **无有效训练数据**：先生成并验证分片。验证集为空或命题与训练集交叉时脚本拒绝训练。
- **长度上限需要增加**：当前上限为 8,192 token；训练、长度预检与推理应保持一致。进一步增加之前，必须重新运行真实模型压力检查，不直接套用基础模型的长上下文上限。
- **分数合理但决策错误**：这是语义质量问题，检查状态、任务边界、标签和独立评估，不能通过修 JSON 字段解决。
