## 每题固定 10 条

| 槽位 | 类型 | 场景要求 | case_type |
|---|---|---|---|
| 01 | Choice | 信息清楚，明确匹配一个类别 | 明确匹配 |
| 02 | Choice | 两个类别容易混淆，但有区分线索 | 易混类别 |
| 03 | Choice | 核心事实缺失或确实存在歧义 | 信息不足 |
| 04 | Choice | 否定、纠正、引用或无关干扰；仍只问一个维度 | 否定或干扰 |
| 05 | Score | 明确符合较低等级 | 低等级 |
| 06 | Score | 中间等级或相邻等级边界 | 中间或边界等级 |
| 07 | Score | 明确符合较高等级 | 高等级 |
| 08 | Noul | 有直接证据支持肯定 | 明确肯定 |
| 09 | Noul | 有直接证据支持否定，不能只是没提到 | 明确否定 |
| 10 | 混合 | 同一新状态下恰好 1 Choice + 1 Score + 1 Noul | 混合独立问题 |

槽位编号、题型组成、`sample_id`（`Txxxx-NN`）不得改动。命题编号不得写进 state。

## 长度要求：每题恰好 9 短 1 中

- 短：该请求**所有问题、所有候选中最长的完整编码输入** ≤ 512 token。
- 中：同样口径 513—1,024 token。
- 一题 10 条中恰好 9 条短、1 条中；中档所在槽位可在本题内轮换，但题型组成不变。
- 不允许超过 1,024 token 的样本。计的是 token，不是字符数，不是 state 字符数，也不是 `usage` 累计值。

中档不能靠机械重复填充。用有意义的多轮对话、工单历史、规则与记录组合形成自然长度。

**实测比例（本地 Qwen tokenizer，单问题、4 个候选）：** 完整输入 token ≈ 0.5 × state 中文字符数 + 60。因此中档样本的 state 通常需要约 900—1,900 个中文字符；短档 state 应控制在约 850 字符以内。混档（槽位 10）有三个问题，同样按最长候选归档，实际预算更紧，建议多测。

**发布前必须逐题实测**，不要靠估算：

```powershell
.\.venv\Scripts\python.exe -m scripts.draft_lengths data/drafts/T0061.jsonl ... --enforce-mix
```

该工具按请求打印每条 token 数与档位，并在不满足 9 短 1 中时以非零退出码失败。不满足就改草稿再测，直到全部通过。

## 质量约束（与 `docs/4` 一致，此处为可执行清单）

- 十条必须在事实、措辞、任务边界和噪声上有实质变化，至少变化两项；不能只换姓名、金额、商品名。
- 每题至少 1 条结构化 state；**每批（20 题）至少 5 条数组 state、5 条结构化 instructions、5 个结构化候选描述**。
- 槽位 03 必须真正缺决定性信息；槽位 09 必须有直接反证，不能只是“没提到”。每 5 题至少 1 条槽位 10 的 Noul 判断尚未知事实，覆盖证据不足。
- 证据充分性与事实真伪分开：缺记录可给低 noul 的“是否足以确认”；事实未知给约 0.5。
- Score 只能衡量一个有序维度，等级互斥且边界清楚，不能把无序类别编号当分值。`legend` 与 `criteria` 由工具派生，不手写。
- Choice 有层级包含关系时必须写明排除条件或判断优先级，或提供“信息不足”类别。
- 概率与证据强弱一致，和为 1；避免全部固定向量、避免 Choice 一律首项获胜。不输出伪精确小数、负数、NaN。
- 不得出现 `confidence`、`reasoning`、`rationale`、`think`。`review.evidence` 每个问题至少 8 字。
- 状态叙述、问题说明、候选描述以中文为主，自包含；涉及政策、合同、医学、技术规范时把判断所需规则写进 state 或 instructions，不依赖现实法规猜测。
- 情感题：明确说话者、对象、时间段；区分中性、混合、证据不足；槽位 09 的否定要有明确反证。
- 意图题：明确目标说话者与当前有效诉求；区分咨询、计划、执行、否定、取消、改口；引用他人诉求与已撤回诉求不生效。
- 每题所有场景只进入该命题固定 `split`，不得改动划分。

## 发布与验证

逐题发布（`finalize_shard` 不覆盖已有分片，已存在则先核对）：

```powershell
.\.venv\Scripts\python.exe -m scripts.finalize_shard data/drafts/T0061.jsonl
```

全部 20 题发布后：

```powershell
.\.venv\Scripts\python.exe -c "from openjev.data import validate_shards; from pathlib import Path; import sys; ids=['T0061','T0062']; rows=validate_shards([Path('data/shards')/f'{t}.jsonl' for t in ids]); print(len(rows))"
.\.venv\Scripts\python.exe -m scripts.preflight_data --topics T0061 T0062 ... --enforce-mix
```

`--topics` 后必须列出本人全部 20 个命题 ID。不要用按 25 题划分的 `--group` 代替 20 题任务校验。

## 语义复核（必做）

- 完整复核至少 4 个命题的全部 10 条，覆盖槽位 03、04、06、09、10。
- 其余每题至少检查一个边界样本（03 或 09）。
- 复核问题：只凭 state 与 instructions 能否支持标签？候选是否互斥？明确否定与未提及是否区分？概率是否匹配证据？十条是否只是换名字？请求是否夹带答案、review 或命题编号？
- 发现问题先改草稿、重新发布（已有分片需先备份为 `data/shards/Txxxx.jsonl.before_fix` 之类再覆盖），再重新校验。
